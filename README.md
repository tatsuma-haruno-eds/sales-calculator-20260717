2.2 診断計算機能
2.2.1 借入可能額計算
計算ロジック:
年収倍率法
一般的倍率: 年収 × 6倍
安全倍率: 年収 × 5倍
積極倍率: 年収 × 8倍
返済比率法
保守的: 年収の25%以内
標準的: 年収の30%以内
積極的: 年収の35%以内
既存借入考慮
車ローン月額 = 残高 ÷ 60（5年返済想定）
その他借入月額 = 残高 ÷ 60
クレカ月額 = 利用額 × 0.15（リボ15%想定）
可処分収入 = 月収 - 既存借入月額合計
2.2.2 月々返済額計算
計算式: 元利均等返済
月額返済額 = 借入金額 × 金利(月利) × (1+月利)^返済回数 ÷ ((1+月利)^返済回数 - 1)
計算パラメータ:
借入金額: 物件価格 - 頭金
返済回数: 希望返済期間 × 12ヶ月
月利: 年利 ÷ 12

# 住宅ローン診断ツール 設計書（v0.2）

対象: Next.js 16 (App Router) / TypeScript / Vercel ｜ 作成日: 2026-10-16 ｜ 元資料: 住宅ローン診断ツール 要件定義書

## 0. 設計方針サマリ

- **計算・保存・PDF生成はすべて端末内（クライアント完結）**。個人情報はサーバーに一切送らない。
- サーバー側は「静的配信 + 最小限のRoute Handler（設定配信・ヘルスチェック・簡易認証）」のみ。DB・外部API・常駐サーバーは使わない。
- **PWA化**し、初回ロード後はオフラインで全機能が動く。
- 運用はGit push → Vercel自動デプロイ。金利などの設定値は設定ファイル（＋環境変数）で更新できる。
- 本書の「暫定」「既定」は私の提案値。最終章の確認事項で合意を取りたい。

## 1. 要件の読み取りと設計上の解釈

要件定義書の記述に曖昧・矛盾する点があったため、次のとおり解釈して設計した。

| 論点 | 要件の記述 | 本設計での解釈（暫定） |
| --- | --- | --- |
| 判定基準の境界 | 25% / 26-30% / >30% で隙間がある | 返済比率: ≤25%緑、25%超〜30%以下黄、30%超赤。年収倍率: ≤6倍緑、6倍超〜7倍以下黄、7倍超赤。**総合判定は悪い方を採用** |
| 返済比率の定義 | 「年収に占める返済比率」 | 既存借入を含む**総返済負担率**を判定に使用。新規ローンのみの比率も併記 |
| 積極倍率8倍と赤判定(>7倍) | 借入可能額の積極8倍と判定基準が不整合 | 借入可能額は「目安上限」、判定は「入力された希望条件」に対して行う |
| 保存先 | localStorage暗号化 | ご指定どおりlocalStorageを採用し、暗号鍵のみ**IndexedDB**に分離して保管（Q1確定） |
| 全削除と誤削除復旧 | 完全削除と復旧が両立 | 削除データは**7日間ゴミ箱**に保持。「完全削除」でゴミ箱・鍵まで消去 |
| 外部送信なしと監視/KPI | エラー監視・月間診断数の計測が必要 | 端末内カウンタ＋エクスポートで集計（Q3） |
| 年齢・勤続年数・家族構成 | 入力項目だが計算での用途なし | 年齢は**完済時年齢チェック**に使用。勤続年数1年未満は注意表示。家族構成は表示・PDFのみ |
| 稼働率99.9% | 数値のみ記載 | 初回ロード後はオフライン動作のため実質影響なし。配信側はVercel Proを前提（Q9） |

### 2.3 Next.js 16 の使い方

- App Router。レイアウトとシェルはServer Component、診断UIはClient Component。
- `params` / `searchParams` は非同期（Promise）として扱う。
- 旧 middleware は **proxy.ts**。簡易認証ゲートとセキュリティヘッダに使用。
- Turbopack（既定）でビルド。`/result?id=` のようにクエリで履歴IDを渡し、静的出力を維持（`useSearchParams` は Suspense で包む）。
- キャッシュは `/api/config` の `Cache-Control` のみで制御。複雑なキャッシュ機能は使わない。

## 3. 計算仕様

計算ロジックは `lib/calc/` の純粋関数（副作用なし）に集約し、UIから独立してテストする。

### 3.1 前提パラメータ（すべて設定値）

| 項目 | 既定値 |
| --- | --- |
| 月収 | 年収 ÷ 12（税込） |
| 既存借入月額 | 車ローン残高 ÷ 60 ＋ その他借入残高 ÷ 60 ＋ カード利用額 × 0.15 |
| 審査金利（借入可能額の逆算用） | 3.5% |
| 完済時年齢の上限 | 80歳（超過は警告のみ、入力はブロックしない） |
| 概算手取り率（ドーナツグラフ専用） | 年収の80% |

### 3.2 借入可能額（3パターン）

- **A. 年収倍率法**: 保守5倍 / 標準6倍 / 積極8倍 × 年収。
- **B. 返済比率法**: 月返済上限 ＝ 年収 × 比率（25/30/35%）÷ 12 − 既存借入月額（0未満は0）。これを審査金利・希望返済期間で元利均等の元本に逆算する。
- **パターン別の借入可能額** ＝ min(A, B)。保守＝（5倍, 25%）、標準＝（6倍, 30%）、積極＝（8倍, 35%）。
- 参考として「購入可能な物件価格目安」＝借入可能額＋頭金 を併記。

### 3.3 月々返済額・金利パターン

- 元利均等返済。借入金額＝物件価格−頭金、回数＝期間×12、月利＝年利÷12。
- 金利0%の場合は 借入金額 ÷ 回数（ゼロ除算回避）。
- 金利は要件の3タイプ×3水準（最低/標準/上限）を `config/rates.json` に定義。**主表示は標準金利**、最低〜上限をレンジ表示。
- 固定10年は、11年目以降を「再設定想定金利」で残高・残期間から再計算（既定は同タイプの上限金利、Q7）。

### 3.4 諸費用（既定は自己資金＝現金支払い想定、Q6）

| 項目 | 式 |
| --- | --- |
| 登記費用 | 物件価格 × 0.5% |
| 融資手数料 | 借入金額 × 2.2% |
| 火災保険 | 50万円（定額） |
| 印紙税・その他 | 物件価格 × 0.3% |

- 団信は金利に含む。合計は物件価格比（%）も表示する。
- 例: 3,500万円・頭金350万円なら約147万円（約4.2%）。要件の「約3-8%」は注記として表示。

### 3.5 適正判定

| 判定 | 返済比率（既存込み） | 年収倍率 | 色/アイコン | 推奨アクション |
| --- | --- | --- | --- | --- |
| 無理なく返済可能 | ≤25% | ≤6倍 | 緑 / ○ | そのまま検討可能 |
| やや厳しい | 25%超〜30% | 6倍超〜7倍 | 黄 / △ | 条件見直し推奨 |
| 要再検討 | 30%超 | 7倍超 | 赤 / × | 大幅な条件変更が必要 |

- 金利タイプごとに標準金利で判定。色だけに依存せず、アイコン形状と文言を必ず併記（カラーユニバーサル）。
- 追加の警告表示: 完済時年齢>80歳、勤続年数1年未満。

### 3.6 条件変更シミュレーション

- **繰上返済**: 期間短縮型／返済額軽減型、一括／毎年定額、実施時期・金額を指定。
- **金利変動リスク**: 開始年と上昇幅（+0.5 / +1.0 / +2.0pt）を指定し、月額・総利息の増減を表示。
- **期間短縮**: 期間を5年刻みで変えたときの月額・総利息の差。
- 年次返済表は12か月ごとに集計（年間返済額・元本・利息・残高・累計利息）。

### 3.7 丸めと検証

- 月額は円単位に丸めて償還表を生成。毎月の利息は円未満切り捨て、**最終回で残高0に調整**。総額は償還表の合計とする。
- 金額表示は円単位、入力は万円単位（Q4と併せて確認）。
- Excel の PMT 関数と照合した**ゴールデンテスト20ケース以上**（境界値・金利0%・期間10年/35年）を必須とする。

## 4. データ設計

### 4.1 診断レコード（概念）

| フィールド | 内容 |
| --- | --- |
| id | UUID |
| createdAt / updatedAt | 日時 |
| memo | 任意メモ（お客様名の代わりに使える。匿名運用が既定） |

年次返済表は容量削減のため保存せず、`input` と `ratesSnapshot` から再計算する。

### 4.2 保存領域

| キー | 内容 | 暗号化 |
| --- | --- | --- |
| mld:history | 診断履歴（最大10件） | ○ |
| mld:trash | 削除済み（7日保持） | ○ |
| mld:draft | 入力途中の下書き（前回入力の復元用） | ○ |
| mld:settings | 表示・自動クリア設定 | × |
| mld:audit | 監査ログ（直近200件、個人情報なし） | × |

### 4.3 暗号化と整合性

- AES-256-GCM（Web Crypto API）。IVは書き込みごとにランダム生成。
- 鍵は初回起動時に**抽出不可のCryptoKey**として生成し、IndexedDBに保管（localStorageには暗号文のみを置き、IndexedDBはこの鍵専用）。
- GCMの認証タグで改ざん検知。復号失敗時は該当データを隔離して通知。
- 任意機能として、起動時のPINロックを用意（Phase 1.5）。
- iOS Safariは一定期間未使用でデータが削除され得るため、**ホーム画面に追加して使う運用**と `navigator.storage.persist()` の要求、定期バックアップを案内する。

localStorageの容量上限（約5MB）に対し、履歴10件は暗号化後も数十KB程度の想定で余裕がある。容量超過や書き込み失敗時は保存エラーを表示し、古い履歴の整理を促す。

### 4.4 履歴・削除・バックアップ

- 履歴は最大10件。11件目の保存時は確認のうえ最古を自動削除（設定でON/OFF）し、ゴミ箱へ移す。
- 削除・自動削除はゴミ箱に7日間保持（復旧可能）。「完全削除」で履歴・ゴミ箱・下書き・設定・監査ログ・暗号鍵をすべて消去。
- 自動クリア: 手動／アプリ終了時（pagehide、ベストエフォート）／最終操作からの経過時間（次回起動時に判定）。
- バックアップ: パスフレーズ指定の暗号化ファイル（PBKDF2-SHA256 + AES-GCM）をエクスポート。インポートは「置換／マージ」を選択でき、一覧から選んだ履歴のみの部分復旧も可能。
- 監査ログ: 閲覧・保存・削除・エクスポート・印刷の日時、操作種別、対象IDのみ記録。

### 5.3 診断結果 `/result?id=`

- **上部サマリ**: 総合判定（アイコン＋色＋文言）と推奨パターンのハイライト。
- **金利タイプ別カード（3枚）**: 月々返済額、返済総額、利息総額、諸費用概算、年収に占める返済比率、判定アイコン。主表示は標準金利で、最低〜上限のレンジを併記。
- **金利水準の切替**（最低／標準／上限）で全表示が連動。
- **借入可能額パネル**: 保守／標準／積極の3パターンと物件価格の目安。
- **タブ**: グラフ／年次返済表／シミュレーション。
- **アクション**: 保存、印刷・PDF（→ `/print`）、比較へ、条件を変更（入力値を保持して `/input` へ）。
- グラフ4種（月額比較の棒、総額内訳の円、残高推移の折れ線、年収比のドーナツ）は Recharts を動的インポートし、判定色に連動。色だけでなくラベルとパターン（白黒印刷対応）でも識別。

### 5.4 比較 `/compare`

- 比較対象: 保存済み診断2〜3件、条件変更前後、金利タイプ間のいずれかを選択。
- 並列表示で差額・差率を強調。**推奨案の自動判定ルール**: 判定ランク → 返済比率の低さ → 総支払額の少なさ の順。
- 条件変更シミュレーター: 頭金・期間・金利水準・物件価格のスライダーで即時再計算し、「この条件を保存」で履歴へ。

### 5.5 履歴 `/history`

- 日時・メモ・物件価格・標準変動金利の月額・判定の一覧（最大10件）、詳細表示（→ `/result`）、削除（ゴミ箱へ）。
- 「ゴミ箱」タブで7日以内の削除分を復旧。部分復旧は選択した件のみ。

### 5.6 設定 `/settings`

- **表示**: 文字サイズ（標準／大／特大）、匿名モード（既定ON）。
- **データ管理**: 自動クリア（アプリ終了時／経過時間）、エクスポート／インポート、ゴミ箱、監査ログ閲覧、完全削除。
- **情報**: アプリ版数、金利設定の版数・更新日、免責事項、会社情報。

### 5.7 印刷プレビュー `/print?id=`

- A4プレビュー（`@page` 指定、ページ番号・ヘッダー/フッター・会社ロゴ・連絡先）。
- 設定: 匿名化、含める項目（グラフ／年次表）、白黒モード（パターン塗り）。
- 操作: **印刷**（ブラウザ印刷。iPadは共有メニューでPDF保存）／**PDFダウンロード**（クライアント生成、目標3秒以内）。
- 構成は要件のとおり: 表紙 → 入力条件 → 診断結果（比較表・判定・グラフ画像）→ 詳細（年次表・諸費用）→ 注意事項・免責。

## 6. API仕様

**原則: 診断入力・結果などの個人情報はAPIに一切送らない。** APIはアプリ運用のための最小限のみ。

| メソッド | パス | 認証 | 用途 | キャッシュ |
| --- | --- | --- | --- | --- |
| GET | /api/health | 不要 | 稼働確認（status、アプリ版数、金利設定版数、時刻） | no-store |
| GET | /api/config | 必要 | 金利・前提パラメータ・免責文・会社情報の配信 | s-maxage=300, stale-while-revalidate |
| POST | /api/auth/login | 不要 | パスコード検証、署名付きCookie発行 | no-store |
| POST | /api/auth/logout | 必要 | Cookie破棄 | no-store |

- **/api/config**: `RATES_JSON` があればそれを、なければ `config/rates.json` を返し、Zodで検証。検証失敗時は500とし、クライアントは同梱の既定値で動作を継続。クライアントは「同梱既定値で起動 → バックグラウンドで取得 → 版数が新しければ保存して次回診断から適用」。診断途中で金利が切り替わらない。
- **認証**: httpOnly / secure / SameSite=Lax のセッションCookie（ブラウザー終了時まで保持、HMAC署名）。パスコード比較はタイミング攻撃対策付き。総当たり対策はVercelのファイアウォール（レート制限ルール）で設定。
- **エラー形式**: `{ "error": { "code": "...", "message": "..." } }`。
- オフライン時は `/api/config` をService Workerのキャッシュから返し、未取得なら同梱既定値を使用。
- 将来候補（Phase 2）: `POST /api/diagnose`（サーバー側検証用。既定は無効）。

### ローカル開発での認証設定

ルートの `.env` に `APP_ACCESS_PASSCODE` を設定してください。セッション署名に別の秘密鍵を使う場合は、32文字以上のランダムな `SESSION_SECRET` も設定します。`SESSION_SECRET` が未設定の場合は `APP_ACCESS_PASSCODE` を署名鍵として使用します。`.env.example` は設定例であり、実際の秘密情報はコミットしないでください。

## 9. 非機能要件の実現方針

| 要件 | 方針 |
| --- | --- |
| 計算1秒以内 | 純粋関数でミリ秒オーダー。入力はデバウンスし、結果はメモ化 |
| 初期ロード3秒以内 | グラフ・PDFライブラリを動的インポートし、初期JSを軽量に保つ。フォントはサブセット＋preload |

| メモリ100MB以内 | 履歴は最大10件。画像は破棄。Chromeの計測で確認 |
| オフライン | Service Workerでアプリシェル・設定JSON・フォントをプリキャッシュ。初回は必ずオンラインで起動し、ホーム画面に追加 |

| 個人情報保護 | 外部送信なし、サードパーティスクリプト・アナリティクスなし、ログに個人情報を出さない |
| 免責 | 結果画面・PDFに固定の注意事項（概算、法的効力なし、金融機関の審査とは別）を表示 |
